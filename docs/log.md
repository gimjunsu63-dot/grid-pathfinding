## 2026-11-19 (5회차, 11/16 회차가 밀려서 진행)

- 한 일: 8방향 이동(대각선 14, 직선 10, 벽 모서리 통과 금지), JPS, 교통 정체 실험(도로 비용 1, 정체 칸 0~50%),
  8방향 탐색 그림. 옥타일 거리 함수 octile()은 직접 작성. 실험 전체 다시 실행.

- 주제를 바꾼 이유:
  중간 발표 계획대로 BFS·다익스트라·A*를 비교해 보니 수업 내용을 측정으로 확인하는 수준이었다.
  그런데 비용이 다르거나 미로·정체가 있는 지도에서 A*가 다익스트라보다 느려지는 결과가 나왔고,
  원인은 휴리스틱이 실제 남은 비용을 얼마나 정확하게 짐작하느냐였다.
  그래서 주제를 "휴리스틱 정확도가 A* 탐색 성능에 미치는 영향"으로 바꾸기로 했다.

- 결과 보고 의외였던 것:
  교통 정체가 10%만 돼도 A*가 다익스트라를 따라잡혔다 (정체 0%에서는 약 4.7배 빨랐음).
  그때 맨해튼 짐작의 정확도는 100%에서 약 75%로 떨어졌다.

- 왜 그런지 내 생각:
  맨해튼 거리는 정체를 모른다. 정체가 곳곳에 흩어져 있으면 실제로는 돌아가야 해서 실제 비용이 짐작보다 커지고,
  A*는 짐작만 믿고 들어갔다가 막혀서 옆 칸을 계속 열어 보게 된다. 결국 다익스트라처럼 사방을 다 본다.

- 막힌 것 / 고친 것:
  - octile 짠 과정: 먼저 손으로 정리함
    dr = 행 차이, dc = 열 차이
    대각선 이동 수 = min(dr, dc), 직선 이동 수 = max(dr, dc) - min(dr, dc)
    비용 = 대각선 × 14 + 직선 × 10
  - 처음 붙여 넣었을 때 IndentationError(들여쓰기가 너무 깊음) → 당겼더니 return이 함수 밖으로 나가서 SyntaxError
    → 함수 본문은 전부 공백 4칸으로 맞춰야 한다는 걸 알게 됨. 고친 뒤 옥타일 테스트 6개, 전체 74개 통과

- 궁금한 것:
  정체를 반영한 짐작을 만들면 A*가 다시 이길까? → 랜드마크 실험으로 확인하기로 함

- 왜 그런지 내 생각:
  직선거리를 지도에서 제일 빠른 속도(고속도로)로 나눠서 짐작이 실제의 20%밖에 안 된다.
  탐색 지점은 32% 줄었지만 지점마다 계산이 더 들어서 오히려 느려졌다. 격자에서 맨해튼이 비용 1~9 지도에서 진 것과 같은 이유다.
  짐작이 실제보다 크다고 바로 틀리는 건 아니다. 최단 경로 위에서 짐작이 넘친 정도가
  두 번째로 좋은 길과의 차이보다 커야 다른 길을 먼저 고른다.
  그래서 "짐작이 큰 지점 비율"만 보고는 틀릴지 알 수 없고, 질의가 어디를 지나는지가 중요하다. (질의마다 확인은 못 했다)
