# 다익스트라 · 맨해튼 A\* · 랜드마크 A\* 비교: 휴리스틱 정확도가 탐색 성능에 미치는 영향

[![test](https://github.com/gimjunsu63-dot/grid-pathfinding/actions/workflows/test.yml/badge.svg)](https://github.com/gimjunsu63-dot/grid-pathfinding/actions/workflows/test.yml)

2026-2 고급알고리즘 개인프로젝트 · 2026193209 김준수

장애물이 있는 2차원 격자 지도에서 출발 칸부터 도착 칸까지 비용이 가장 작은 경로를 찾는 문제를,
짐작(휴리스틱)에 쓰는 정보가 다른 세 방법으로 같은 조건에서 비교합니다.

| 방법 | 짐작에 쓰는 정보 |
| --- | --- |
| 다익스트라 | 없음 (h = 0) |
| A* + 맨해튼 거리 | 지도 모양만 (벽과 칸 비용은 모름) |
| A* + 랜드마크 | 기준점에서 미리 재 둔 실제 거리 (벽, 비용, 정체 반영) |

출발점은 BFS · 다익스트라 · A* 비교(실험 A~E)였고, 거기서 "A*는 짐작이 부정확한 지도에서 다익스트라보다
느려진다"는 결과가 나와 짐작의 정확도 자체를 주제로 삼았습니다. 정확도를 일정하게 조절한 기준
(실제 남은 비용 × k)을 측정 도구로 써서 정확도와 탐색량의 관계를 재고, 랜드마크 개수와 미리 계산 비용,
지도가 바뀌는 상황까지 봅니다. 마지막으로 실제 도로지도(송도, OpenStreetMap)에서 시간대별 정체를 넣어 같은 질문을 다시 확인합니다.

- 저장소는 [`algorithm-env`](https://github.com/lec-algorithm/algorithm-env) 템플릿으로 만들었습니다.
- Python 표준 모듈만 씁니다 (외부 라이브러리 없음).

## 실행 방법

Codespaces나 `docker compose exec lab bash`로 컨테이너에 들어간 뒤:

```sh
make test          # 유닛 테스트
make run           # 작은 예제 지도 3개에서 세 알고리즘 실행
make maps          # 지도 종류별 작은 샘플 출력
make bench         # 실험 전체 실행 -> results/*.csv (수 분)
make bench-quick   # 실험 전체를 아주 작은 지도로 빠르게 (동작 확인용)
make figures       # 지도별로 세 알고리즘이 탐색한 칸과 경로를 그림으로 -> figures/maps/
make analyze       # results/*.csv로 그래프와 표 만들기 -> figures/charts/, figures/RESULTS.md
make summary       # 결과 한 장 요약 (조건별로 누가 이겼나 + 핵심 숫자) -> 터미널 + figures/SUMMARY.md
make results       # bench + analyze + summary + figures 한 번에 (Codespaces에서 약 22분)
```

**결과 보기**: [`figures/SUMMARY.md`](figures/SUMMARY.md) (한 장 요약), [`figures/RESULTS.md`](figures/RESULTS.md) (그래프와 표), [`figures/README.md`](figures/README.md) (지도별 탐색 범위 그림)

실험 하나만 다시 돌릴 때:

```sh
python3 src/bench.py --exp A          # 실험 A만 (그다음 make analyze)
python3 src/bench.py --exp C D        # 실험 C, D만
python3 src/bench.py --maps 3 --repeats 2   # 지도 수, 반복 수 바꾸기
```

컨테이너 없이도 Python 3.11 이상이면 같은 명령으로 돌아갑니다.

## 구현 규칙

비교가 공정하도록 세 알고리즘이 다음을 똑같이 따릅니다.

| 항목 | 규칙 |
| --- | --- |
| 입력 | `(grid, start, goal)`, 위치는 `(행, 열)` |
| 출력 | `SearchResult(path, cost, expanded, stale, max_frontier)` |
| 이동 | 상하좌우 4방향, 이웃 칸 순서 고정 (위, 아래, 왼쪽, 오른쪽) |
| 비용 | 들어가는 칸의 비용을 더함 (출발 칸 비용은 안 냄), 장애물은 0 |
| 종료 | 도착 칸을 큐/힙에서 **꺼낼 때** 종료 |
| 다익스트라 | A*에서 h = 0인 경우. 코드 하나(`best_first`)를 같이 씀 |
| A* 휴리스틱 | 맨해튼 거리. 칸 비용이 1 이상이라 실제 비용보다 크지 않으므로 최적 보장 |
| A* 동점 처리 | 기본은 f가 같으면 g가 큰 칸 먼저 (`tie_break` 인자로 바꿀 수 있음) |

측정값 정의:

| 이름 | 뜻 |
| --- | --- |
| `expanded` | 큐/힙에서 꺼내서 처리한 칸 수 (이미 확정된 칸의 낡은 항목은 제외) |
| `stale` | 꺼냈지만 낡은 항목이라 버린 수. `heapq`에 값 갱신 기능이 없어 같은 칸을 여러 번 넣기 때문 (BFS는 항상 0) |
| `max_frontier` | 탐색 중 큐/힙 크기의 최댓값 (낡은 항목 포함, 실제로 차지한 메모리 기준) |

## 지도

모든 지도는 시드가 같으면 항상 똑같이 만들어집니다. 장애물과 칸 비용은 서로 다른 난수열에서
뽑기 때문에, 시드가 같으면 비용 1 지도와 비용 1~9 지도의 장애물 배치가 완전히 같습니다.

| 종류 | 설명 | 출발 → 도착 |
| --- | --- | --- |
| `random` | 칸마다 `wall_ratio` 확률로 장애물 | 왼쪽 위 → 오른쪽 아래 |
| `maze` | 재귀 백트래킹 미로 (스택으로 구현해서 재귀 한도 없음). `loop_ratio`로 벽을 더 뚫어 순환 경로 추가 | 왼쪽 위 → 오른쪽 아래 미로 칸 |
| `nopath` | 연결된 랜덤 지도에서 도착 칸을 벽으로 막음. 세 알고리즘 모두 도달 가능한 칸을 전부 탐색해야 하는 최악의 경우 | 왼쪽 위 → 오른쪽 아래 |
| `uwall` | 빈 지도에 출발 쪽으로 입구가 열린 U자 벽. A*가 휴리스틱을 따라 U자 안으로 들어갔다가 돌아 나오는 함정 | 왼쪽 가운데 → 오른쪽 가운데 |
| `terrain` | 비용 1~9가 덩어리로 모여 있는 지형 (value noise). 장애물 없음 | 왼쪽 위 → 오른쪽 아래 |
| `city` | 건물 블록 사이 도로망. 간선도로 1, 일반 도로 3, 정체 구간 9, 도로 일부 통제(벽) | 왼쪽 위 → 오른쪽 아래 |

**연결 규칙**: `random`과 `city`는 출발과 도착이 이어지지 않으면 같은 시드의 다음 난수로
지도를 다시 뽑고, 몇 번 만에 뽑혔는지(`attempts`)를 CSV에 기록합니다.

**랜덤 출발·도착**: 출발 칸과 같은 연결 영역 안에서 두 칸을 무작위로 고르되, 맨해튼 거리가
(가로 + 세로) / 4 이상인 쌍만 씁니다.

## 실험

기준 조건은 **크기 200 × 200, 랜덤 장애물 20%, 비용 1, 모서리 출발·도착**이고,
실험마다 이 중 하나만 바꿉니다.

| 실험 | 바꾸는 것 | 조건 |
| --- | --- | --- |
| A | 지도 크기 | 50, 100, 200, 400 |
| B | 장애물 비율 | 0, 10, 20, 30% |
| C | 지도 종류 | 랜덤, 미로, 순환 미로, 경로 없음, U자 벽, 도시(비용 1) |
| D | 비용 | 랜덤·도시 지도 비용 1 vs 비용 다름, 지형 |
| E | 출발·도착 | 모서리 고정 vs 랜덤 (비용 1, 비용 1~9) |
| T | A* 동점 처리 | f가 같을 때 g 큰 칸 먼저 / g 작은 칸 먼저 / 넣은 순서 |
| W | 가중치 A* | h에 1, 1.5, 2, 3, 5를 곱함 (다익스트라와 비교) |
| H | 우선순위 큐 | `heapq`(C로 구현) vs 파이썬으로 짠 이진 힙, 같은 탐색 코드 |
| BI | 양방향 탐색 | 다익스트라, A*, 양방향 다익스트라 (모서리 / 랜덤 출발·도착, 지도 종류별) |
| O | 8방향 이동 | 대각선 이동 허용 (대각선 비용 14, 직선 10), A*는 옥타일 거리, JPS 추가 |
| J | 교통 정체 | 도시 지도에서 모든 도로 비용 1, 정체 칸(비용 9) 비율만 0~50%로 바꿈 |
| **HQ** | **휴리스틱 품질 (본 실험)** | 다익스트라, A* + 맨해튼, A* + 랜드마크 1·2·4·8·16개, 정확도 측정 도구 k = 0.25~1.5. 비용 1~9 랜덤 지도, 미로, 정체 20% 도시. 출발·도착 랜덤 |
| **DY** | **동적 환경 (본 실험)** | 정체 20% 도시에서 랜드마크를 잰 뒤 교통이 바뀜: 정체 생김 +10·30·50%, 정체 풀림 10·30·50%. 예전 랜드마크 그대로 vs 다시 계산 vs 맨해튼 vs 다익스트라. 지도 30개 |
| **RM** | **실제 도로지도** | 송도 도로망(OpenStreetMap), 시간대 12개(3~21시), 출발·도착 30쌍. 다익스트라, A* + 직선거리, 랜드마크(그 시간에 잼 / 밤에 잼 / 8시에 잼) |
| LP | 랜드마크 위치 | 서로 가장 먼 칸 / 모서리 / 랜덤, 랜드마크 4·8개. HQ와 같은 지도 3종 |
| noise | 측정 흔들림 | 같은 지도를 30번씩 반복해 시간이 얼마나 흔들리는지 |

A~E와 noise는 BFS · 다익스트라 · A* 세 가지를, 나머지는 표에 적은 알고리즘들을 비교합니다.

**8방향 규칙**: 상하좌우와 대각선으로 움직이고, 벽 모서리를 스치는 대각선 이동은 막습니다
(대각선으로 지나가는 두 칸이 모두 열려 있어야 함). 그래서 4방향과 갈 수 있는 영역이 같습니다.
비용은 정수로 다루려고 10배 단위를 씁니다 (직선 10 × 칸 비용, 대각선 14 × 칸 비용).
JPS는 비용이 모두 같은 지도에서만 정답을 보장하므로 비용 1~9 조건에서는 돌리지 않습니다.

측정 규칙:

- 조건마다 지도 10개(시드 2026~2035) × 지도마다 5번 반복
- 반복할 때마다 알고리즘 실행 순서를 돌림 (항상 같은 알고리즘이 먼저 돌지 않게)
- 탐색 함수 호출만 시간을 잼 (`time.perf_counter_ns`). 지도 생성과 기준값 계산은 제외
- 시간을 재는 동안 가비지 컬렉터를 멈춤
- 매 실행마다 결과를 검사: 다익스트라, A*, 양방향 다익스트라는 최적 비용이어야 하고,
  BFS는 최적보다 작을 수 없고, 가중치 w인 A*는 최적의 w배를 넘을 수 없음. 어긋나면 실험이 에러로 멈춤
- 예전 랜드마크(DY)는 비용이 오르기만 한 조건에서는 최적이어야 하고(아래 이론), 정체가 풀린 조건에서만
  더 비싼 경로를 허용해서 얼마나 틀렸는지 기록함

결과 CSV의 한 줄은 "지도 하나에서 알고리즘 하나를 한 번 실행한 결과"이고, 같이 저장되는 기준값은
열린 칸 수(`open_cells`), 출발에서 도달 가능한 칸 수(`reachable`), 맨해튼 거리(`manhattan`),
최적 비용(`optimal_cost`)입니다. 실행한 컴퓨터, Python 버전, 커밋은 `results/<실험>.env.json`에 남습니다.

## 휴리스틱 품질 실험 (HQ)

- **정확도** = 도착점에 갈 수 있는 모든 칸에서 (짐작 ÷ 실제 남은 비용)의 평균. 1이면 완벽, 0이면 다익스트라.
  실제 남은 비용은 도착점에서 다익스트라를 한 번 돌려서 구합니다 (시간 측정에는 안 들어감).
- **측정 도구 h = k × 실제 남은 비용**: 답을 미리 알아야 쓸 수 있으므로 비교 대상이 아니라 "정확도가 k일 때
  탐색량이 얼마인가"를 재는 자입니다. k ≤ 1이면 최적 경로가 보장되고, k > 1이면 최대 k배까지 비싼 경로를 낼 수 있습니다.
- **랜드마크**: 기준점(랜드마크)에서 모든 칸까지 다익스트라로 거리를 미리 재 두고, 삼각부등식으로
  남은 비용의 하한을 짐작합니다. 칸에 들어갈 때 비용을 내는 지도라서 A→B와 B→A 비용이 다르므로,
  경로를 뒤집으면 성립하는 d(b→a) = d(a→b) + cost[a] − cost[b]를 써서 양방향 하한을 둘 다 씁니다.
  랜드마크는 서로 가장 먼 칸을 차례로 고릅니다 (모서리·랜덤 선택도 지원).
- **미리 계산 시간**(`prep_ms`)은 탐색 시간과 따로 재서 CSV에 남기고, "몇 번 찾아야 본전인가"
  (미리 계산 시간 ÷ 한 번 찾을 때 줄어든 시간)를 함께 계산합니다.
- 출발·도착이 모서리로 고정이면 첫 랜드마크가 출발이나 도착 바로 위에 놓여 짐작이 우연히 완벽해지므로,
  이 실험은 출발·도착을 랜덤으로 뽑습니다.

## 동적 환경 실험 (DY)

랜드마크는 지도가 바뀌기 전에 재 둔 거리라서, 교통이 바뀐 뒤에도 그대로 써도 되는지가 문제입니다.

- **정체가 생기면(비용이 오르기만 하면) 예전 거리를 그대로 써도 최단 경로가 보장됩니다.**
  예전 지도에서 h_old(v) ≤ d_old(v→t)이고, 비용이 오르기만 했으니 d_old(v→t) ≤ d_new(v→t)입니다.
  이웃 칸 사이의 일관성도 h_old(u) ≤ c_old(u,v) + h_old(v) ≤ c_new(u,v) + h_old(v)로 유지됩니다.
  대신 짐작이 덜 정확해져서 느려집니다.
- **정체가 풀리면(비용이 내려가면) 보장이 깨집니다.** 실제 거리가 예전보다 짧아져서 짐작이 실제보다
  커질 수 있고, A*가 더 비싼 경로를 낼 수 있습니다.
- 바뀐 지도: 정체 생김 x% = 정체 아닌 도로 칸의 x%가 정체(비용 9)로 바뀜, 정체 풀림 x% = 정체 칸의 x%가 비용 1로 바뀜.
  벽은 그대로라 연결 상태는 같고, 칸마다 난수를 하나씩 뽑아서 큰 변화가 작은 변화를 포함합니다.
- 비교: 다익스트라, A* + 맨해튼, 랜드마크 8개를 바뀐 지도에서 다시 계산, 예전 랜드마크 8개를 그대로 사용.
  다시 계산하는 비용(`prep_ms`)과 "몇 번 찾아야 다시 계산한 게 본전인가"를 함께 계산합니다.
- 지도마다 질의가 하나라서, 틀린 질의 비율을 세기 위해 지도를 30개 씁니다.
- 짐작이 실제보다 큰 칸의 비율(`h_over`)도 모든 칸에서 셉니다 (실제보다 크지 않은 짐작이면 0).

## 실제 도로지도 실험 (RM)

격자 대신 실제 도로망에서 같은 질문을 확인합니다.

- **지도**: [`data/songdo_roads.json`](data/README.md). 송도국제도시 일대 자동차 도로를 OpenStreetMap에서 한 번 받아
  저장했습니다(`python3 tools/fetch_osm.py`). © OpenStreetMap contributors, ODbL 1.0.
  일방통행을 지키고, 모든 지점끼리 오갈 수 있는 가장 큰 부분만 씁니다.
- **비용**: 도로 구간 하나를 지나는 시간(0.1초 단위 정수). 자유 주행 속도는 도로 종류별 기본값
  (고속도로 100, 간선 60, 보조 간선 50·40, 생활 도로 30 km/h)이고, `maxspeed`가 있으면 그 값을 씁니다.
- **시간대별 정체 (모델)**: 실제 교통량이 아니라 규칙으로 만든 모델입니다(`src/roads.py`).
  출퇴근 시간(8시, 18~19시)에 큰길이 더 많이 느려지고, 구간마다 늘 막히는 정도(시드 고정)와 시간마다 조금씩 흔들림을 넣었습니다.
  밤(23~5시)은 자유 주행이고, 어느 시간도 밤보다 빠르지 않습니다.
- **비교**: 다익스트라, A* + 직선거리(직선거리 ÷ 지도에서 가장 빠른 속도: 실제보다 클 수 없음, 맨해튼의 도로판),
  랜드마크 8개를 그 시간에 잰 것 / 밤(3시)에 잰 것 / 출근 시간(8시)에 잰 것.
- **이론**: 밤은 가장 빠른 시간이라 밤에 잰 랜드마크는 어느 시간에나 실제보다 크지 않습니다(DY와 같은 이유).
  실험에서 매 실행 최단 경로인지 검사합니다. 8시에 잰 랜드마크는 덜 막히는 시간에 실제보다 커질 수 있습니다.
- 도로망은 방향이 있는 그래프라서 랜드마크마다 정방향(L→x)과 역방향(x→L) 다익스트라를 한 번씩 돌립니다.
- 지도 파일이 없으면 RM은 건너뜁니다.

## 랜드마크 위치 실험 (LP)

같은 개수라도 어디에 두느냐에 따라 정확도가 달라집니다. 서로 가장 먼 칸을 차례로 고르기(경로 비용 기준),
지도 모서리(그다음 변의 가운데), 랜덤(시드 고정) 세 가지를 랜드마크 4개, 8개로 비교합니다.

## 분석

`make analyze`가 `results/*.csv` 원본에서 다시 계산해서 그래프와 표를 만듭니다. 쓰는 지표:

| 지표 | 계산 |
| --- | --- |
| 시간 | 지도 10개 × 5번 실행의 중앙값, 사분위 범위(IQR) 함께 |
| 기울기 | 로그-로그 그래프에서 칸 수에 대한 기울기 (1이면 칸 수에 비례) |
| 칸당 시간 | 시간 ÷ 탐색한 칸 수 (마이크로초) |
| 탐색 비율 | 탐색한 칸 ÷ 출발에서 도달 가능한 칸 |
| 휴리스틱 정확도 | 출발점의 맨해튼 거리 ÷ 최적 비용 |
| A* 작업 비율 | 같은 지도에서 A* 탐색 칸 ÷ 다익스트라 탐색 칸 |
| 비용 비율 | 찾은 경로 비용 ÷ 최적 비용 |
| 짐작 정확도 (HQ·DY·LP) | 갈 수 있는 모든 칸에서 짐작 ÷ 실제 남은 비용의 평균, 실제보다 큰 칸의 비율 |
| 코드 줄 수 | 함수별 줄 수 (빈 줄, 주석, 독스트링 제외) |

알고리즘별 색은 모든 그림에서 같습니다: BFS 파랑, 다익스트라 청록, A* 주황, 랜드마크 보라(예전 랜드마크는 연한 보라 점선), 양방향 회색, JPS 분홍.

## 탐색 범위 그림

`make figures`를 실행하면 지도 종류마다 BFS · 다익스트라 · A*가 탐색한 칸과 찾은 경로를
나란히 그린 PNG가 `figures/maps/`에 생기고, 한눈에 보는 페이지 [`figures/README.md`](figures/README.md)가 만들어집니다.

탐색한 칸은 알고리즘 코드를 고치지 않고 기록합니다. 세 알고리즘 모두 칸 하나를 처리할 때
`grid.neighbors()`를 정확히 한 번 부르기 때문에, 이 호출을 기록하는 격자(`RecordingGrid`)를 넘기면
실제 코드가 실제 순서대로 탐색한 칸이 남습니다. 기록한 칸 수가 알고리즘이 보고한 `expanded`와
같은지도 테스트로 확인합니다.

## 테스트

`make test`가 확인하는 것:

1. 손으로 답을 아는 작은 지도 (막힌 길, 출발=도착, 출발/도착이 벽, 경로 없음, 비용 때문에 BFS가 틀리는 지도)
2. 랜덤 지도 300개에서 다익스트라·A* 비용을 **별도로 짠 참조 구현**(단순 반복 완화)과 비교
3. 랜덤 지도에서 세 알고리즘끼리 일치하는지
4. 지도 생성: 같은 시드면 같은 지도, 출발·도착은 항상 열린 칸, 연결 여부, 완전 미로는 트리 구조,
   큰 미로(401 × 401)에서도 재귀 에러 없음, U자 벽이 직선 경로를 막는지, 지형 비용이 실제로 뭉쳐 있는지
5. 측정 코드: 작은 실험을 돌려서 CSV 줄 수, 최적 비용 검사, 실행 순서 교대가 맞는지
6. 그림 코드: 기록한 탐색 칸 수 = `expanded`, 기록해도 결과가 같은지, PNG 파일 형식이 맞는지
7. 추가 알고리즘: 직접 짠 힙이 `heapq`와 같은 순서로 꺼내는지, 어느 힙을 써도 탐색 결과가 똑같은지,
   양방향 다익스트라를 참조 구현과 랜덤 지도 300개에서 비교, 가중치 A* 비용이 최적의 w배 이내인지
8. 분석 코드: 작은 실험 전체로 그래프·표를 끝까지 만들어 보고, SVG 형식이 맞는지
9. 8방향과 JPS: 옥타일 거리 값과 "실제 비용보다 크지 않음", 모서리 통과 금지, 다익스트라·A*·양방향을
   8방향 참조 구현과 비교, JPS를 다익스트라와 랜덤 지도 1,500개에서 비교
10. 랜드마크: 짐작이 실제 남은 비용보다 절대 크지 않은지(모든 칸), 이웃 칸 사이에서도 일관적인지,
   랜드마크 A*가 다익스트라와 같은 비용을 내는지, 측정 도구의 정확도가 정확히 k인지, 랜드마크를 늘리면 정확도가
   떨어지지 않는지, 거리 계산이 참조 구현과 같은지
11. 동적 환경: 정체가 생기면 비용이 오르기만 하고 벽은 그대로인지, 정체가 풀리면 내려가기만 하는지,
   정체가 생긴 뒤에도 예전 랜드마크가 모든 칸에서 실제보다 크지 않고 일관적이며 A*가 최적인지,
   정체가 풀리면 예전 짐작이 실제보다 커지는 칸이 실제로 생기는지, 세 가지 위치 선택 모두 최적 경로를 내는지
12. 실제 도로지도: 제한 속도 읽기, 일방통행(`yes`, `-1`), 서로 오갈 수 없는 구간 제거, 어느 시간도 밤보다 빠르지 않은지,
   직선거리 짐작이 실제보다 크지 않고 일관적인지, 밤에 잰 랜드마크가 모든 시간대에서 안전한지,
   8시에 잰 랜드마크가 밤에는 실제보다 커지는지, A*·랜드마크가 다익스트라와 같은 비용을 내는지
